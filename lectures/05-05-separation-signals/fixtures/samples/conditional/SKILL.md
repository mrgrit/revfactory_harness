# db-migration

마이그레이션 파일은 `db/migrations/` 아래에 `YYYYMMDDHHMM_<slug>.sql` 로 만든다. 한 파일에는 한 가지 변경만 담는다.

## 기본 절차

1. 현재 스키마 버전을 확인한다: `make db-version`
2. 파일을 만든다: `make db-new name=<slug>`
3. `-- up` 과 `-- down` 두 구간을 모두 채운다. `down` 이 비어 있는 파일은 리뷰에서 반려된다.
4. 로컬에 적용한다: `make db-up`
5. 되돌려 본다: `make db-down && make db-up`
6. 테스트를 돌린다: `make test-db`
7. PR 본문에 마이그레이션 파일명과 예상 실행 시간을 적는다.

## 작성 규칙

- 컬럼 이름은 `snake_case`, 불리언은 `is_` 접두사.
- 새 컬럼에는 기본값을 준다. `NOT NULL` 은 기본값과 함께만 쓴다.
- 인덱스 이름은 `idx_<table>_<columns>`.
- 외래키는 `ON DELETE` 동작을 반드시 명시한다.

## 운영 스키마를 변경할 때만

운영 DB 에 이미 데이터가 있는 테이블의 스키마를 바꿀 때만 아래 절차를 추가로 따른다. 로컬 전용 테이블이나 빈 테이블은 기본 절차로 충분하다.

### 사전 점검

- 대상 테이블의 행 수를 잰다: `SELECT COUNT(*) FROM <table>;` — 100만 행 이상이면 DBA 에게 창을 잡아 달라고 요청한다.
- 대상 테이블을 참조하는 외래키를 모두 나열한다: `make db-fk table=<table>`
- 현재 잠금 대기 세션이 없는지 본다: `make db-locks`
- 복제 지연을 확인한다. 5초를 넘으면 시작하지 않는다.

### 백업

```bash
make db-snapshot name=pre_<slug>
make db-snapshot-verify name=pre_<slug>
```

스냅샷 검증이 실패하면 진행하지 않는다. 검증 로그를 PR 에 첨부한다.

### 무중단 컬럼 추가

1. 컬럼을 `NULL` 허용으로 먼저 추가한다. 기본값은 이 단계에서 주지 않는다.
2. 애플리케이션이 새 컬럼에 쓰기 시작하도록 배포한다.
3. 기존 행을 배치로 채운다. 한 배치는 5,000행, 배치 사이에 200ms 대기.
   ```sql
   UPDATE <table> SET <col> = <expr>
   WHERE id IN (SELECT id FROM <table> WHERE <col> IS NULL LIMIT 5000);
   ```
4. 모든 행이 채워진 것을 확인한 뒤 `NOT NULL` 과 기본값을 건다.
5. 각 단계는 별도 마이그레이션 파일로 만든다. 한 파일에 합치지 않는다.

### 무중단 컬럼 삭제

1. 애플리케이션에서 해당 컬럼 참조를 모두 제거하고 배포한다.
2. 하루 동안 에러 로그에 컬럼 이름이 나오지 않는지 확인한다.
3. 컬럼 이름을 `_deprecated_<col>` 로 바꾸는 마이그레이션을 먼저 적용한다.
4. 일주일 뒤 실제로 삭제한다.

### 인덱스 생성

- 반드시 `CREATE INDEX CONCURRENTLY` 를 쓴다. 트랜잭션 안에서는 동작하지 않으므로 파일 상단에 `-- no-transaction` 을 적는다.
- 생성 후 `pg_stat_user_indexes` 에서 실제로 사용되는지 일주일 뒤 확인한다.

### 롤백 계획

- `down` 구간이 데이터 손실을 일으키는 경우(컬럼 삭제, 타입 축소)에는 `down` 대신 스냅샷 복구 절차를 적는다.
- 롤백 명령을 실제로 스테이징에서 한 번 실행해 본 기록을 PR 에 남긴다.
- 롤백에 5분 이상 걸리면 배포 창을 다시 잡는다.

### 적용 당일

1. 배포 채널에 시작을 알린다. 대상 테이블·예상 시간·롤백 담당자를 적는다.
2. `make db-up env=prod` 를 실행하고 출력을 그대로 채널에 붙인다.
3. 적용 후 10분간 에러율과 p95 응답 시간을 본다.
4. 이상이 없으면 종료를 알리고, 스냅샷은 7일 뒤 삭제한다.

## 데이터 이관

테이블 간 데이터 이관은 마이그레이션이 아니라 스크립트(`scripts/backfill/`)로 한다. 마이그레이션 파일에 대량 `UPDATE` 를 넣지 않는다.

## 출력 형식

- 마이그레이션 파일 전체 내용을 코드 블록으로.
- 예상 실행 시간과 잠금 여부를 한 줄로.
